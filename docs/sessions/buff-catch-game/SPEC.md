# SPEC — BUFF Catch (משחקון יומי)

**Slug:** `pkg/buff-catch-game` · **Phase:** MVP · **סטטוס:** Plan Mode (טרם אושר לבנייה)
**מקור:** הצעת שני (tester), 2026-06-13 · **גרסה:** v1 — בלי מטבע, בלי גייט-משימות

---

## 1. מטרה
לתת לילדים **סיבה משחקית יומית לפתוח את BUFF** שאינה מטלה — עוגן הנאה קצר שמחזק את ההרגל. נולד מהצורך שזוהה אחרי המלחמה (ההרגל שביר; רוב הילדים לא חזרו).

## 2. החלטות ליבה (נעולות)

### 2.1 בלי מטבע (v1)
המשחק **לא נותן ולא לוקח BUFFs**. השיא הוא "personal best" אישי בלבד, מנותק מהכלכלה.
**סיבה:** כלכלת ה-BUFF שברירית (אין ledger, exploits פתוחים, מאזנים מנופחים). חיבור מטבע בשלב הזה מסכן את כל המערכת.

### 2.2 בלי גייט-משימות (decision 2026-06-13)
המשחק **לא ננעל מאחורי משימות**, ומשימות **לא** "פותחות" משחקים.
**סיבה:** "משימות → גישה למשחק" = מילולית מודל **Joon** (*"Extrinsic: coins for game access"*, PRD §3.2), שהמוצר מגדיר את עצמו נגדו. נבחנו גייט-50% וגם "כל משימה = משחק" — שניהם הופכים את ה-Pillar-1 מ"אני רוצה" ל"אני חייב". נפסלו.
**חיבור-למשימות בעתיד (v2, אופציונלי):** הדרך הכשרה היחידה היא **מתנת BUDDY** (BUFF_VALUES: *"BUDDY נותן מתנות בתגובה לימים מוצלחים"*) — אחרי יום טוב ה-BUDDY מפתיע ב-bonus round כמתנה, לא כעסקה-לכל-משימה.

### 2.3 מוגבל, לא אינסופי
תקרת **משחקים יומיים שטוחה** (ברירת מחדל מוצעת: 3 ליום), מתאפסת בחצות. לא בליעת-זמן (אירוני באפליקציית ADHD). **לא** קשורה למשימות.

## 3. מיקום (decision 2026-06-13)
**כרטיס במפקדה → מסך משחק נפרד.** לא טאב, לא כניסה מוסתרת.
- **כרטיס כניסה** ב-`ChildDashboardScreen` (טאב "מפקדה", שכבר נושא אייקון game-controller) — נראות יומית מקסימלית.
- **המשחק עצמו** = route חדש `BuffCatchScreen` ב-Stack של הילד, **מסך מלא** (push) — ממוקד ואימרסיבי.
- **לא טאב נפרד:** 5 טאבים הם כבר הגבול הנוח; טאב 6 מעלה משחקון לדרגת פונקציית-ליבה — לא פרופורציונלי ונוגד את מודל ה"מוגבל".

## 4. Scope

**בפנים (v1):**
- כרטיס כניסה במפקדה (שיא + כפתור "שחק" + אינדיקציית משחקים שנותרו היום)
- `BuffCatchScreen`: 30 שניות, באפים קופצים אקראית, טאפ לתפיסה
- האצה הדרגתית (מהיר יותר עם הזמן)
- "באף זהב" נדיר (×3) להפתעה
- מסך סיום: ניקוד + שיא אישי + משפט BUDDY + "שחק שוב" (אם נשארו משחקים) / "סיום"
- שמירת שיא + מונה-משחקים-יומי per-child
- ערכת נושא לפי הילד אוטומטית (ThemeContext — Mint/Gamer)

**בחוץ (נדחה):**
- כל קשר ל-BUFFs / כלכלה (v2)
- חיבור-למשימות כלשהו — רק v2 כמתנת BUDDY
- לוחות תוצאות / השוואה בין ילדים (סותר Pillar 3 — לא ייכנס)
- מוקשים / עונשים / "משימות רודפות" (סותר Pillar 2 — נפסל)
- סאונד (low-effort, אפשר בהמשך)

## 6. כיוונון מנגנון (ראשוני, לאיזון בבדיקות)
- משך סבב: **30ש'**
- חלון נראות באף: 1.4ש' → 0.8ש' (לינארי לאורך הסבב)
- מרווח הופעה: 900ms → 450ms
- מקס' באפים בו-זמנית: 3
- סיכוי באף-זהב: 8% (×3 נקודות)
- תקרת משחקים יומית: **3** (ברירת מחדל — open question #1)

## 7. נתונים ושמירה
- **שיא:** AsyncStorage `buffcatch:best:{childId}` — בלי שינוי schema.
- **משחקים-היום:** AsyncStorage `buffcatch:plays:{childId}:{date}` — מונה, מתאפס לפי תאריך.
- חוצה-מכשירים (אם אותו ילד על 2 מכשירים) נדחה ל-v2 (עמודת profiles). לרוב (65% חולקים מכשיר) מקומי מספיק.
- **אפס כתיבה ל-credit/balance.**
- **View-as-Child:** השיא/המונה תחת ה-`childId` הנכון, לא ההורה.

## 8. גישה טכנית (בלי dependencies חדשים)
- `src/screens/child/BuffCatchScreen.tsx` + route ב-Stack של הילד
- כרטיס כניסה ב-`ChildDashboardScreen`
- Game loop: `requestAnimationFrame`/`setInterval` עם cleanup ב-`useEffect`
- באפים: `Animated.View` (RN מובנה), מיקום אקראי ב-state
- אפס ספריות חיצוניות → **לא Improvement Package של dependency**

## 9. Edge cases
- יציאה מהמסך באמצע סבב → ניקוי טיימרים, בלי קריסה
- רקע/מסך כבוי → השהיה או סיום נקי
- מסכים קטנים → אזור משחק רספונסיבי, אצבע-בטוח
- חצות באמצע משחק → המונה מתאפס לסבב הבא, לא קוטע סבב פעיל

## 10. טלמטריה
event פשוט: `buff_catch_played` (childId, score, isNewBest) — לבדיקת ההשערה שהמשחקון מחזיר ילדים (הנתון שמצדיק v2).
