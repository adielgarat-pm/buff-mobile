## איך לעשות את ה-Cross-Reference

### Option A: ידנית
1. פתחי את רשימת 47 ה-Lovable emails שיש לך (Gmail / Sheet / Lovable Supabase dashboard)
2. לכל אחד מ-14 השמות למעלה — חפשי match לפי שם פרטי בלבד
3. סמני matches בטבלת ה-match למטה
4. ב-email outreach (per [KIT §2.2](../../BUFF_FOUNDING_100_KIT.md)), השתמשי בשם הפרטי שמצאת ב-match
5. ל-non-matches: pass לכתיבה generic

### Option B: ידנית-חכמה (אם הרשימה ב-Sheet)
1. שמרי את 14 השמות בטבלה חדשה ב-Sheet שלך
2. השתמשי ב-VLOOKUP / MATCH function על השם הפרטי
3. הריצי על 47 ה-emails — צפויות 6-10 התאמות (לא כולם בעלי משפחה מרובת-ילדים בהכרח רשמו את שמם המלא)

### Option C: דרך CC (אם תיתני את הרשימה)
- תעלי את 47 ה-emails כקובץ CSV / paste ב-chat
- אני אריץ matching אוטומטי (display_name vs email local-part vs full_name field)
- אחזיר טבלה מסודרת

בלי match (default):
> *"Hi [first name from email — best guess],"*

עם match (high-engagement Lovable user):
> *"Hi [actual first name they used in Lovable],*
>
> *זאת עדי — היית מ-47 הראשונות ב-BUFF המקורית, ובאמת השתמשת בה: יצרת משפחה עם [N] ילדים. אני אסירת תודה ש-נתת לזה צ'אנס. הנה ההצעה רק לכן..."*

ה-personalization הזה (אזכור ספציפי של ה-engagement שלהם) מעלה את ה-conversion rate משמעותית. ה-warm list של 47 + הסיגנל הזה = פוטנציאל של 8-15 sales מהקבוצה הזאת לבד.

## למה הרשימה הזאת לא enough לבד

ה-14 ההורים האלה הם profile rows בלי auth — אין להם email בתוך ה-DB. ה-emails שלהם נמצאים ב-Lovable POC backup (ע"ב מסמך הזיכרון `project_lovable.md` — "49 users backed up"). בלי הצלבה ידנית, אני יכול רק לתת את השמות. ה-emails חייבים להגיע ממך.

אם תעלי את ה-Lovable backup ל-`~/buff-mobile/lovable-poc-backup.csv` או דומה, אני יכול לעשות את ה-matching ב-30 שניות בסשן הבא.
