## הבעיה (Why)

תובנת ה-AI (Smart Insight / "המאמן") נוצרה **פעמיים בלבד אי-פעם** — שתיהן פנימיות (Itay + Test Child), אחרונה ב-2026-06-26, אפס הצבעות 👍👎. הסיבה היא לא איכות אלא **חשיפה**: התובנה קבורה במסך Insights הפנימי, מאחורי שרשרת שערים (חזרה ליום 3 → ניווט פנימה → entitlement → auto-generate שרץ רק בתוך המסך).

בינתיים כרטיס התובנה בדשבורד — המקום שכל הורה פעיל כן רואה — מציג תובנה **rule-based** גנרית (`useParentInsights`, תבניות i18n לפי אחוזי השלמה) שלדעת Adi ממילא לא רלוונטית.

**ההחלטה:** להחליף את תוכן כרטיס התובנה בדשבורד בתובנת ה-AI, ולהעלות את ה-lazy auto-generate מהמסך הפנימי אל הדשבורד.

נתוני רקע (Supabase, 2026-07-14):
- 37 משפחות עם entitlement; רק 6 פעילות ב-14 יום האחרונים; רק 4 עם 3+ ימי פעילות.
- ה-LLM בפועל: Anthropic API (`generate-child-insights` edge function), לא Gemini.
- מגבלה קיימת: 3 יצירות/שבוע/ילד (server-enforced), חינם בווב (#317), שער entitlement באנדרואיד (402).

## Goals

1. תובנת ה-AI מוצגת **בדשבורד ההורה** — המסך הראשון שכל הורה פעיל רואה — במקום התובנה ה-rule-based.
2. ה-auto-generate (Phase E של ai-trial) עולה מהמסך הפנימי אל הדשבורד: הורה זכאי עם מספיק דאטה מקבל תובנה בלי אף לחיצה.
3. שמירה על כל בקרות העלות הקיימות: שימוש חוזר בתובנה שמורה (`child_insights.smart_insight`), מקסימום auto-generate אחד לשבוע לילד, כיבוד מגבלת 3/שבוע של השרת.
4. Platform parity: עובד ב-web (חינם) וב-Android (entitled/trial) כאחד.

## Non-goals

- **לא** מוחקים את מנוע ה-rule-based (`useParentInsights`) — הוא ממשיך להזין את מסך Insights הפנימי (Highlights, weekly map, framing) ומשמש fallback.
- **לא** משנים את ה-prompt, מגבלת 3/שבוע, או שער ה-entitlement בשרת. (חריג יחיד ב-edge function: החלפת ספק ה-LLM ל-Gemini — Phase 0.)
- **לא** מוסיפים בחירת ילד לדשבורד — נשאר "הילד הראשון" כמו היום.
- **לא** נוגעים בהפצת התובנה בערוצים חיצוניים (push/email) — חבילה נפרדת, תלויה בתיקון האקטיבציה.

## Behavior Contract

מטריצת המצבים של כרטיס התובנה בדשבורד אחרי החבילה:

| מצב | מה מוצג |
|---|---|
| יש `smart_insight` שמור | **כרטיס AI**: headline + message + action + CTA (ניווט לפי `cta_type`) + **חותמת "נכון ל-{תאריך}"** (computed_at). הקשה על הכרטיס → מסך Insights |
| אין תובנה שמורה + זכאי (entitled/trial או web) + `activeDays ≥ 2` + נותרו יצירות השבוע | **auto-generate שקט** (spinner קצר על הכרטיס) → כרטיס AI. מוגן: ניסיון אחד לילד לשבוע, נרשם ב-storage מקומי כדי לא לירות בכל mount |
| אין תובנה + זכאי אבל אין מספיק דאטה (`activeDays < 2`) | כרטיס "נעול — עוד X ימי פעילות" (המצב הקיים `insightsLocked`, ללא שינוי) |
| אין תובנה + לא זכאי (Android free) | **Teaser כמו היום**: תובנת rule-based אחת + badge Premium + CTA ל-Paywall (בכפוף לשאלה פתוחה 1) |
| auto-generate נכשל (שרת/רשת/rate-limit) | fallback שקט לכרטיס ה-rule-based הקיים; בלי הודעת שגיאה בדשבורד |
| תובנה שמורה משבוע קודם + זכאות לשבוע חדש | מנסה auto-generate חדש; **עד שמצליח — מציג את הישנה עם התאריך שלה** (החלטת Adi 2026-07-14: תובנה תקפה עד שהבאה מחושבת; אין פקיעה קשיחה) |

עקרונות רוחביים:
- **אפס יצירות מיותרות:** קריאת ה-DB (`get_smart_insight_state`) תמיד קודמת; יצירה רק כשאין תובנה שמורה לשבוע הנוכחי.
- **הצבעות 👍👎 מוצגות גם על כרטיס הדשבורד** (החלטת Adi, 2026-07-14) — שורת משוב קטנה בתחתית הכרטיס, אותו מנגנון (`record_insight_vote`, הצבעה אחת לשבוע לילד). הצבעה בדשבורד ובמסך Insights מסונכרנת (אותו state דרך `useSmartInsights`). הוספת הקשר הורה (`parent_context`) נשארת במסך Insights בלבד.
- הכרטיס לעולם לא מציג מספר/אחוז של הילד — רק את טקסט המאמן.
- **שקיפות זמן:** כל תובנה מציגה מתי חושבה ("נכון ל-{תאריך}"). אין מצב שהורה רואה תובנה בלי לדעת על איזו תקופה היא מדברת.

## API / Route Changes

- **חילוץ hook משותף** — הלוגיקה של lazy auto-generate (כיום inline ב-`ParentInsightsScreen.tsx:103-115`) עוברת ל-hook משותף (למשל `useAutoCoachInsight(childId)`) שבו משתמשים גם הדשבורד וגם מסך Insights, כדי שלא יהיו שני עותקים של אותם guards.
- `ParentDashboardScreen.tsx` — מוסיף `useSmartInsights(firstChildId)` + ה-hook הנ"ל; ענף הרנדור של `insightCard` מוחלף לפי מטריצת ה-Behavior Contract. ההצבעה בדשבורד משתמשת ב-`userVote`/`submitVote` שכבר קיימים ב-hook — אין RPC חדש.
- אין נתיבי ניווט חדשים; ה-CTA `cta_type` ממופה לאותם יעדים כמו במסך Insights (bonus/sticker/med/rewards).
- **RPC `get_smart_insight_state`** — מורחב להחזיר גם `computed_at` (קיים כבר בטבלה `child_insights`) כדי שהכרטיס יציג "נכון ל-{תאריך}". שינוי additive, לא שובר את הקליינט הקיים.
- **Phase 0 — החלפת ספק LLM ל-Gemini** (החלטת Adi, מיושר לסיכום המקורי): ב-`generate-child-insights/index.ts`, בלוק הקריאה ל-`api.anthropic.com` (מודל `claude-haiku-4-5`) מוחלף בקריאה ל-Gemini API (`generativelanguage.googleapis.com`, מודל `gemini-2.5-flash`) עם `responseMimeType: 'application/json'` (מייתר את חילוץ ה-JSON ברגקס). ה-prompt עצמו לא משתנה. דורש secret חדש `GEMINI_API_KEY` ב-Edge Functions. פריסה מחדש של הפונקציה + בדיקת איכות עברית לפני Phase 1.

## UI Changes

- כרטיס הדשבורד (entitled): מחליף את פריסת "אחוז ענק + תווית" בפריסת מאמן — headline מודגש, message, action, שורת CTA, ושורת משוב 👍👎 בתחתית. שומר על אותו רקע accent וגודל כרטיס (`minHeight: 80`).
- שורת המשוב: שני אייקונים קטנים, לא דומיננטיים; אחרי הצבעה — מצב selected (כמו במסך Insights). ההצבעה לא מסתירה את הכרטיס ולא משנה את תוכנו.
- מצב יצירה: spinner + microcopy קצר ("BUFF חושב על השבוע של {name}…" / "Looking at {name}'s week…") — i18n בשני השפות.
- Teaser לחינמיים: ללא שינוי ויזואלי (בכפוף לשאלה פתוחה 1).
- RTL + עברית: טקסט התובנה מגיע מהשרת בשפת ה-UI — לוודא יישור נכון בשתי השפות.
