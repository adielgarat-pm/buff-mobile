## חלק 2 — Phase 3 saga (מה לקח 3 שעות)

### Bug #4 (the one that wasn't actually stale localStorage)

The 2026-05-05 EOD diagnosed Bug #4 as "stale browser session in localStorage,
fix is 5-10 min: clear storage + sign in fresh." This was wrong.

After clearing storage and signing in with a new Magic Link, the user STILL
landed on /access-denied. The real cause was deeper.

### Investigation timeline

1. **Initial hypothesis (wrong):** UUID mismatch in admin_users.
   Verified via SQL: UUID matches. Ruled out.

2. **Second hypothesis (wrong):** EXECUTE permission missing on is_admin function.
   Verified: `authenticated` role has EXECUTE. Ruled out.

3. **Third hypothesis (partially right):** Race condition between
   `onAuthStateChange` setting session and `RequireAdmin` checking isAdmin.
   Applied Fix A (await checkIsAdmin) and Fix B (explicit uid param) in `26e44c1`.
   Did NOT solve the bug.

4. **Fourth hypothesis (wrong):** `getSession()` inside checkIsAdmin returning
   null due to async storage hydration race. Passed userId directly from
   AuthContext in `0c2f14a`. Did NOT solve the bug.

5. **Fifth hypothesis (correct):** supabase-js v2 client enters internal
   deadlock state after Magic Link session commit. ANY subsequent call to the
   client (including `auth.getSession()`) hangs indefinitely. Confirmed via
   isolated test button — even the first `await supabase.auth.getSession()`
   inside a manually-triggered function never resolved.

   **Workaround applied in `6b6e75b`:** `checkIsAdmin` now calls PostgREST
   directly via `fetch()`, passing userId and access_token from AuthContext's
   in-scope session object. Zero calls into supabase-js client in the hot
   auth-check path.

   Result: /dashboard renders correctly with "Welcome, adi.elgarat@gmail.com".

### Process learnings

1. **Zombie Vite processes corrupted debugging.** Earlier sessions left dev
   servers running on 5173/5174/5175/5176. The browser was hitting one port
   while CC was building on another. ~30 min lost to "HMR isn't picking up
   the changes." Solution: kill ALL node processes before restart, not just
   the visible terminal tabs.

2. **Console reads as document, not stream.** When testing, the UI showed
   `[TEST] Starting manual RPC test (×12)` with no follow-up logs. The "12"
   indicated 12 click attempts where ONLY the first log fired, rather than
   12 successful runs. This was the smoking gun for supabase-js deadlock —
   the very next `await` in testRPC never resolved.

3. **Claude.ai over-routed through Adi.** For ~3 hours, Claude.ai sent Adi
   numbered procedures for SQL queries, F12 navigation, screenshots, button
   clicks. Adi pushed back: "תמיד דרך CC לכל דבר שהוא יכול מבלי לשאול אותי
   קודם". Rule extracted into CLAUDE.md as "Delegation: CC-First
   Investigation" (PR #9, commit 8d588a2).
