## Open issues + bugs found tonight

### 🐛 Metro bundle compilation timeout

When CC tried to recapture screenshots on the emulator AFTER the data changes, Metro (PID 37004) responded at the manifest endpoint but timed out on the bundle endpoint. Caused a `buff-mobile isn't responding` ANR. Did not investigate root cause — pivoted to "use real phone" path instead. If anyone hits this again: kill PID 37004, `npx expo start --port 8083 --clear` from buff-mobile cwd, wait 60-90s for first bundle.

### 🐛 `@expo/config-plugins` missing from node_modules

When CC tried `eas build:list`, it errored: `Cannot find module '@expo/config-plugins'`. Caused by an incomplete `npm install` state. Fixed by re-running `npm install` (which restored 22 vulnerability warnings — pre-existing, not introduced by us). Lockfile changes are now untracked; `package.json` unchanged. **Recommend Adi review whether to commit the `package-lock.json` changes or revert + investigate.**

### 🐛 `buddy_relationships` trigger creates default row on profile insert

Discovered when CC tried to INSERT a buddy_relationships row for Leia and got a UNIQUE constraint violation. The mobile schema has a trigger on `profiles INSERT WHERE role='child'` that auto-creates a `buddy_relationships` row with defaults. To customize (set name, level, streak, skin), you must UPDATE not INSERT. **Not a bug — by design** — but worth documenting for future cloning efforts.

### 🐛 Branch name reuse — `pkg/fcm-polish` was reused by a different PR

CC opened PR #96 on branch `pkg/fcm-polish`. Later in the day, the same branch name was reused for an unrelated change that became PR #101 (i18n child screens fix). Both merged cleanly. Branch HEAD after both merges ended up at the older commit (`a71a834`) — likely a force-push back. Resolved cleanly via the Verify-Before-Delete protocol when the branches were deleted earlier. **Recommend: avoid reusing branch names within the same day.**
